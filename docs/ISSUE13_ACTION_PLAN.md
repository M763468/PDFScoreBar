# Issue #13 Action Plan: 実行計画の再構築 (2026-03-03)

現状、Issue #13 (Full Pipeline Phase 2: バッチ最適化・モデル永続化・VRAM管理) の基本的な実装は完了していますが、実際の稼働において以下の課題が残っています。

1. **HomrのGPU実行確認不足とエラー**: パイプライン内からの呼び出し時に環境の齟齬（`cv2` エラーなど）が発生しており、正しくGPUが機能しているかのエビデンスが不十分。
2. **ログ過多**: `homr_evaluator.py` などの `eprint` による出力が多すぎ、パイプラインとしての監視性を損なっている。
3. **未解決サブイシュー**: その他の細かい最適化や調整が完了しきっていない。

これらの課題を解決し、Issue #13を完全にクローズするための計画を以下に定めます。

## フェーズ 1: パイプライン実行環境の修復とGPU稼働の確証 (完了)
1. **Pythonインタープリタパスの修正**
   - `main.py` の `pdf_to_images` において `PIPELINE_PYTHON` 環境変数を優先し、コンテナ内では `sys.executable` にフォールバックするよう修正済み。
2. **Homr GPU推論の確実な検証**
   - 実行ログより `CUDAExecutionProvider` の適用と Real-ESRGAN の GPU 稼働を確認済み。

## フェーズ 2: ログ出力の最適化（ノイズの排除） (完了)
1. **`eprint` の `logging` への移行**
   - `homr_evaluator.py` 内で `homr.simple_logging.eprint` をモンキーパッチし、標準出力にあふれるデバッグログを `logger.debug` レベルに抑え込むことで、大幅なクリーン化を達成。

## フェーズ 3: 未解決サブタスク・VRAM管理の最終チェック (進行中)
1. **バッチ処理とVRAMの安全確認**
   - RTX 4060 (8GB VRAM) を前提に、現在の実装（CNNモデルのバッチサイズ64、MMRモデルのサブプロセス化）で本当にピークVRAMが想定内に収まるか、より大きなデータでのストレステスト（またはバッチサイズの調整余地）を確認。
2. **その他残存課題の消化 (完了)**
   - `detection.py` における Homr の完全スキップ処理（無駄なプロセスの起動自体の防止）を実装済み（バッチ内全ファイル存在チェックによるスキップ）。

## フェーズ 4: E2Eでの評価実行とドキュメント化
1. **`evaluation2` データセット全体への適用**
   - 最適化された状態で全ページのパイプライン推論を実行し、完走することを確認。
   - エラー発生時も `--skip-existing` によってリカバリが容易であることを検証。
2. **ドキュメントの更新**
   - `docs/ENVIRONMENTS.md` に最新のGPU実行用コンテナ手順を追記。
   - 次のフェーズへ向けた実績を更新。
