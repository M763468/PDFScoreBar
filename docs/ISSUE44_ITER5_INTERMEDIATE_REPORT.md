# Issue #44 Iter 5 再学習 中間報告 (2026-03-02)

## 1. 概要
本報告は、Issue #44「evaluation2 GTを用いた小節線CNN判定モデルの再学習」における第5イテレーション（Iter 5）の結果をまとめたものである。
本イテレーションでは、Issue #53 で導入された **Gap Rescue（局所再探索）** により救済された候補（Hard Positives）と、探索緩和に伴い増出したノイズ（Hard Negatives）を学習データに含めることで、網羅性の最大化と精度の維持を両立させた。

## 2. 学習データセット (Iter 5)
多様な楽譜スタイルへの汎用性と、特定のノイズ（符幹など）への耐性を高めるため、以下のデータを統合した。

- **evaluation2 (latest)**: 29,277枚（Gap Rescue 有効時の全候補）
- **DeepScores (Dense V2)**: 15,417枚（標準的な小節線と多様な記号ノイズ）
- **合計**: **44,694枚** (TP 23.3% / FP 76.7%)

## 3. 精度評価結果 (evaluation2 全68ページ)

判定閾値 `th=0.1` において、過去最高の Recall を達成した。

| 指標 | Baseline (2/27, th=0.5) | **Iter 5 (現在, th=0.1)** | 改善幅 |
| :--- | :--- | :--- | :--- |
| **Recall (網羅性)** | 98.82% | **99.78%** | **+0.96%** |
| **Precision (正確性)** | 99.97% | **99.83%** | -0.14% |
| **FN (欠落総数)** | 42件 | **8件** | **-34件** |
| **FP (誤検出数)** | 1件 | **6件** | +5件 |

### FN（欠落）の内訳
- **FN_det (候補欠落)**: 4件（プローブが物理的に反応しなかったケース）
- **FN_cnn (判定ミス)**: 4件（候補はあるが CNN スコアが 0.1 未満だったケース）

## 4. 可視化によるエラー分析
残存する 8件の FN のうち、特徴的なケースを `tools/visualize_eval_failures.py` により抽出し、分析した。

### **ケース A: 極薄・かすれによる候補欠落 (FN_det)**
- **該当ページ**: `Sibelius-Violin_Concerto-Viola, page_006` 等
- **状況**: インクが背景と同化するほど薄く、Gap Rescue の緩和閾値（`min_ratio=0.3`）を下回っている。
- **見た目**: 赤枠（GT）内に候補（青枠）が全く存在しない。

### **ケース B: 境界線上での低スコア (FN_cnn)**
- **該当ページ**: `Va_Prokofiev_Symphony1, page_006`, `Va__Prokofiev_Symphony5, page_003 / 023` 等
- **状況**: 候補は正しく抽出されているが、CNN スコアが `0.02` 〜 `0.08` 程度と低く、閾値 `0.1` でフィルタリングされた。
- **見た目**: 赤枠と青枠が重なっているが、付与されたスコアが極めて低い。

## 5. 考察と次の方針
今回の Iter 5 により、実用上ほぼ完璧な Recall（99.8%）を達成した。残る 8件は物理的な限界（インクの消失）か、極めて判断が難しい境界線上のケースに絞られている。

### **次なるアクションの選択肢**
1.  **残存 8件のピンポイント救済**: これらの箇所を学習データに「重み付き」で追加し、Iter 6 として微調整（Fine-tuning）を行う。
2.  **探索パラメータの最終調整**: 特定のスコアに対して Gap Rescue の閾値をさらに 0.1 程度下げる（副作用の FP 増を CNN が抑えきれるか検証）。
3.  **ベースラインの固定**: 現状の精度で十分と判断し、Issue #44 をクローズ、後続の統合プロセス（Issue #19）へ進む。
