# Issue #51 残18件のFN解決ロードマップ：可視化修正と失敗モードの再定義

## 1. 背景と目的
本プロジェクトの最終目標は「楽譜画像への正確な小節番号付与」である。この過程で、小節線の検出器（Detector）および真偽判定モデル（CNN Classifier）の評価を行っている。

現在、Issue #44「evaluation2 小節線CNN再学習」における最新のベースライン（前処理 `croprecenter_v2_ge0p5` 適用時）において、**18件の False Negative (FN：検出漏れ)** が残存している。

これら 18件の FN を詳細に分析した結果、従来の可視化ツールの不備（カテゴリG）が原因で、真の失敗原因を見誤るリスクが判明した。本ドキュメントは、可視化を是正した上で行った精密診断の結果と、最終的な解決ロードマップを記録するものである。

## 2. カテゴリ定義（失敗モードの分類）
分析にあたり、以下のカテゴリを用いて各ケースを分類している。

### 実質的に許容可能なケース（小節数カウントに支障がないもの）
- **カテゴリA（ダブルバー片線）**: 複線（ダブルバー）の片方のみが不検出。もう片方が認識されていれば小節数は正しく数えられる。
- **カテゴリB（複線統合）**: ダブルバーの2本線を一つの領域（bbox）として検出。IoU判定では不合格になる場合があるが、論理的には1イベントとして数えられる。
- **カテゴリC（divisi重複）**: divisi等の縦線重複。
- **カテゴリE（GTミス）**: 実際には小節線でないものが Ground Truth として登録されていたもの（※対処済み）。

### 対処が必要な真の失敗ケース
- **カテゴリD（端線太線）**: 端線の太い部分を誤認し、CNNスコアが低下するもの。
- **カテゴリF（完全ミス）**: 検出器が全く反応していない、あるいは全く別の場所を誤認しているもの。
- **カテゴリG（可視化不備）**: 旧ロジックにおいて、GTの近くに候補がない場合に、遠方の無関係な候補を表示してしまっていたもの。

## 3. 可視化ロジックの是正 (v2)
旧ロジックでは、GTに対して IoU=0 の場合でもページ内で最もCNNスコアが高い候補を選んで表示していた。これがカテゴリGの正体である。

### 修正内容
- **ツール**: `tools/visualize_remaining_fn_v2.py`
- **変更点**: GT中心から **200px 距離閾値** を導入。
- **効果**: 200px 以内に候補がない場合は「NO CANDIDATE NEARBY」と表示し、純粋な「候補欠落」であることを可視化した。これにより、カテゴリGは消滅し、真の失敗原因（タイプ1〜3）が明確になった。

## 5. 改善ロードマップ (実行順序)
探索の改善による Recall（網羅性）向上を優先し、それに伴って混入する FP（偽陽性）を最後に CNN 再学習でクリーンアップする戦略をとる。

### Step 1: 診断の完了 (#51)
- カテゴリGの是正と FN 18件の失敗モード確定、および本ロードマップの合意。

### Step 2: 評価ルールの正式採用 (新規 Issue #52)
- 中心距離ベースの `center_anchor` ルールを標準評価ロジックに組み込む。
- 小節番号カウントに影響しない Cat A-D を形式的に解消し、真の改善対象を絞り込む。

### Step 3: 候補探索の改善 (新規 Issue #53)
- Probe Rescue（局所再探索）を実装し、「候補なし」ケースを物理的に救済する。この段階では FP の増加を許容する。

### Step 4: CNN再学習 Iter 5 (#44)
- 救済された候補（Hard Positive）および、増加した FP を学習データに投入。
- 最終的な Precision / Recall の両立を達成する。

## 6. 結論
是正後の診断により、「アルゴリズムで救うべきもの」と「学習で救うべきもの」の境界が確定した。実際の CNN 再学習 (#44) を実行する前に、Step 2 と Step 3 を完了させることが、Iter 5 を最終的な解決策とするための必須条件である。
