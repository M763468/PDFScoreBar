# ログ・成果物管理ガイドライン

このドキュメントは、プロジェクト内のログおよび中間成果物が無秩序に増加するのを防ぎ、`git worktree` 等の並列環境でも整合性を保つための運用ルールを定めたものです。

## 1. ディレクトリ構造の原則

全ての実行出力およびデバッグ用アセットは、原則として `logs/` ディレクトリ配下に集約します。

### 1.1 カテゴリ分類
`logs/` 配下に以下のサブディレクトリを作成し、用途に応じて使い分けます。これら以外のディレクトリを `logs/` 直下に作成することは原則禁止します。

- `logs/runs/`: パイプライン（`src/pipeline/main.py`）の通常実行結果。
- `logs/eval/`: ベンチマーク評価や精度検証の結果。
- `logs/experiments/`: 新機能やアルゴリズムのプロトタイプ実験。
- `logs/models/`: CNN 等の学習済みモデル（`.pth`）および学習履歴。
- `logs/system/`: システムレベルのログ（コンテナ起動ログ、リソース監視等）。
- `logs/archive/`: 完了したプロジェクトや過去の実験の退避場所。

### 1.2 ディレクトリ命名規則
追跡を容易にするため、各カテゴリ配下では以下の形式でディレクトリを作成します。

`logs/<category>/<task_id>_<timestamp>/`

例: `logs/eval/issue90_20260314_180000/`

## 2. Worktree における共有・独立ポリシー

並列実行環境（`git worktree`）では、以下のルールを適用します。

### 2.1 共有 (Shared)
全 worktree で共通のストレージを参照し、読み取り専用（または一貫性維持が必要な共通資産）として扱います。
- `data/`: 元データ（PDF、画像、GT）。
- `datasets/`: 学習用データセット。
- `logs/models/`: 最新の公式モデル。

### 2.2 独立 (Isolated)
worktree ごとに個別の実体を持ち、実行結果が混ざらないようにします。
- `logs/runs/`, `logs/eval/`, `logs/experiments/`: 実行ごとに新しいディレクトリが生成されるため。
- `artifacts/`: 一時的な検証ログや triage 結果。

## 3. データの「昇格 (Promotion)」と永続化

Worktree 内で生成された重要なログ（例：Issue解決のエビデンス）をメイン環境に持ち帰る、あるいは永続化するための手順です。

### 3.1 昇格コマンド
`make promote-log SRC=<path> DEST=<category>` を使用して、Worktree 内の成果物をメインリポジトリの永続的な `logs/` 配下へ安全に移動します。

## 4. クリーンアップ運用 (`clean-logs`)

`make clean-logs` を実行して不要なファイルを一括削除します。

### 4.1 保護（残すべき）ログの指定
以下の条件に当てはまるディレクトリは `clean-logs` の対象外（保護対象）となります。
- フォルダ内に空の `.keep` ファイルが存在する場合。
- フォルダ名に `_keep_` または `_final_` という文字列が含まれる場合。
- 過去30日以内に作成・更新された最新のログ。

## 5. 既存資産（レガシー）の移行戦略

ルール策定以前に作成された、`logs/` 直下の既存ディレクトリについては以下の通り扱います。

1.  **現状維持 (As-is)**: 過去の報告書等からリンクされているものは移動させず、そのまま保持します。
2.  **随時移行**: 過去の実験を再開したり参照したりする場合は、作業のついでに `logs/<category>/` 配下へ移動し、関連するドキュメントの記述を更新します。
3.  **優先クリーンアップ**: `MANIFEST.md` に記載がなく、かつ GitHub 上でも言及されていないディレクトリは、定期的なクリーンアップの対象となります。

## 6. 記録とエビデンスの管理

新しい評価結果や実験データが生成された際は、**GitHub の Issue コメントまたは Pull Request コメント**にそのパス（例: `logs/eval/issue90_...`）を明記してください。

## 7. 自動化支援

- `make check-consistency`: `MANIFEST.md` に記載のない「迷子（Orphan）」ディレクトリを警告します。
- `make setup-worktree`: Worktree作成、共有ボリュームの設定、独立コンテナの起動を一括で行います。
- **Worktree管理スキル**: AI エージェントは `.agents/skills/worktree-manager` を使用して並列環境の構築とクリーンアップを自律的に行います。
