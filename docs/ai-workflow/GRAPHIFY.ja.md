## 目的

Graphify は、複雑なアーキテクチャ、依存関係、呼び出し経路の質問のための、任意のリポジトリのナビゲーション補助です。現在のソース、テスト、正規のアーキテクチャ文書が引き続き正本です。

通常のコードの質問で、Graphify を必ず最初に使う手順にしないでください。古いグラフを新しいソースより信用しないでください。

## 既存のグラフへの問い合わせ

Graphify が明示的に依頼された場合、または実質的に役立つ場合は、既存のコミット済みのグラフを優先します。

```bash
scripts/graphify_query.sh "<focused question>"
```

回答はソースの確認範囲を絞るために使い、重要な結論は現在のソースとテストで直接確認します。

グラフがない、古い、または不十分な場合は、すぐに通常のリポジトリ検索に切り替えます。

## インストール

Graphify は、タスクがローカルでの Graphify の実行や保守を明示的に必要とする場合にだけインストールします。

```bash
uv tool install graphifyy
graphify install --project --platform agents
```

リポジトリについての質問に答えるだけなら、インストールは不要です。

## 共有する長期の出力

後のナビゲーションを改善する、持ち運び可能な出力だけをコミットします。

- `graphify-out/graph.json`
- `graphify-out/GRAPH_REPORT.md`
- `graphify-out/wiki/**`
- `graphify-out/MANIFEST.json`

キャッシュや状態、`.graphify_*` の付随ファイル、内部の manifest、その場限りのエクスポートは、タスクが明示的に必要としない限りローカルに置きます。

## 更新・再構築

コミット済みの Graphify の成果物を更新するのは、タスクに Graphify の保守が明示的に含まれている場合か、アーキテクチャの大きな変更でコミット済みのグラフが誤解を招く状態になった場合だけです。

無人でのコードのみの更新:

```bash
graphify extract . --code-only --force
graphify cluster-only . --no-viz --no-label
graphify export wiki
```

アーキテクチャを変更する場合の推奨順序:

1. ソースとテストの変更を確定します。
2. 正規のアーキテクチャ文書を更新します。
3. グラフにする正確なソースのリビジョンを固定します。
4. そのリビジョンから Graphify を更新します。
5. `graphify-out/MANIFEST.json.source_base_commit` をそのリビジョンに設定します。
6. 生成された変更を、コミットする前に確認します。

先にグラフを更新し、まだソースで確認していないアーキテクチャの変更の根拠として生成されたグラフを使うことはしないでください。

## 古さ

`source_base_commit` が古い、または利用できない場合は、ソースを直接確認するか、タスクが求める場合に再構築する理由になります。古いグラフの出力を現在の状態として扱ってよい理由には決してなりません。

機能ブランチごとや、文書だけの変更ごとに Graphify を再生成しないでください。

## 意味情報の抽出

文書や画像からの意味情報の抽出は、明示的に選んだ場合だけ行います。APIキーがたまたまあるという理由で始めないでください。先に、意図する範囲、データの安全上の制約、バックエンドとモデル、保持の計画を確認します。

## Web での利用

ローカルの CLI を実行できない Web クライアントは、コミット済みの Graphify の出力をナビゲーションとして使い、現在のソースをリポジトリへの接続で確認できます。更新したように見せるために、生成された出力を手で編集してはいけません。
