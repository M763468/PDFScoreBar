この文書は、このリポジトリでのラベルの使い方を標準化します。一貫したラベルは、自動化、トリアージ、コミュニケーションに欠かせません。
存在するラベルの正本は、リポジトリの GitHub のラベル一覧（`gh label list`）です。`.github/ISSUE_TEMPLATE/` の Issue テンプレートは、一部のラベルを自動で付けます。

## AIエージェント用のラベル

| ラベル | 説明 | 使い方 |
| --- | --- | --- |
| `assign-to-jules` | Google Jules によるリモート実装のきっかけになるラベル。 | Jules に GitHub 側でのリモート実装を始めさせたい場合にだけ使います。 |
| `ai:implement` | AI が実装できるタスクを示す、任意のメタデータのラベル。 | トリアージや検索のための情報用のラベルです。ローカルでの Codex/gemini-cli の協働には不要です。 |
| `ai:review` | AI によるレビューの依頼を示す、任意のメタデータのラベル。 | AI のレビューを明示的に追跡したい PR/Issue に使います。 |

## 状態のラベル

| ラベル | 説明 | 使い方 |
| --- | --- | --- |
| `blocked` | 外部の依存関係や判断待ちで進められない。 | 作業を進められない場合に付けます。ブロックの理由をコメントで説明してください。 |

## 優先度のラベル

| ラベル | 説明 | 使い方 |
| --- | --- | --- |
| `priority:high` | すぐに対応すべき優先度の高いタスク。 | 影響の大きい重大なバグや機能のために取っておきます。 |
| `priority:med` | 中程度の優先度のタスク。 | 計画したワークフローの一部であるほとんどのタスクの既定値です。 |
| `priority:low` | 優先度の低いタスク。 | 小さな改善、リファクタリング、急がない整理に使います。 |

## 規模のラベル

規模のラベルは、必要な作業量を見積もり、Issue を分割すべきかを判断するのに役立ちます。

| ラベル | 説明 | 使い方 |
| --- | --- | --- |
| `scope:small` | 小さく自己完結した変更（例: 1日未満の作業）。 | 個別の関数、バグ修正、小さな文書の更新に向きます。 |
| `scope:medium` | 中程度の規模の変更（例: 1〜3日の作業）。 | 新しい機能や大きめのリファクタリングに向きます。 |
| `scope:large` | 分割が必要になりそうな大きな変更（3日を超える作業）。 | 小さな Issue に分けるべきエピックや複雑な機能に使います。 |

## Issue の種類のラベル

| ラベル | 説明 | 使い方 |
| --- | --- | --- |
| `bug` | バグの報告。 | コードの欠陥を説明する Issue を示します。 |
| `feature` | 機能の要望。 | 新しい機能や機能拡張に使います。 |
| `task` | タスクや雑務。 | 保守、リファクタリング、文書、その他の機能・バグ以外の作業に使います。 |

## その他の使われているラベル

次のラベルはリポジトリに存在しますが、名前と GitHub の説明以上のリポジトリ固有の使い方の規則はありません。説明的に付けるだけにし、自動化には頼らないでください。

| ラベル | 補足 |
| --- | --- |
| `documentation` | 文書の改善や追加。`task` と組み合わせることが多いです。 |
| `enhancement` | GitHub の既定のラベル。`feature` と重なります。 |
| `investigation` | 調査だけの作業。 |
| `refactor`、`regression`、`follow-up` | 説明的な分類。 |
| `ready for review`、`has-pr`、`review-addressed`、`completed` | 状態の目印。これらを付けたり読んだりする自動化はありません。 |
| `duplicate`、`invalid`、`wontfix`、`question`、`good first issue`、`help wanted` | GitHub の既定のラベル。 |
