この文書は、バーライン検出用の正解データ（GT）を作成するときの方針を定めます。特に、複縦線や終止線のような複雑なケースを対象にしています。

## 1. 分類とラベル付けの方針

高品質な検出を確保し、既存データセット（DeepScoresなど）との互換性を保ちつつ将来の機能拡張にも対応できるよう、**マルチラベル・単一イベント**の方式を採ります。

### 1.1 `gt_relabel_gui` で使うラベル
次のラベル（各ボックスの `barline_type` として保存され、既定値は `barline`）は、音楽上の役割に厳密に従って使います。
- **`barline`**: 通常の1本の縦線（単縦線）。
- **`double_barline`**: 区切りや調号・拍子の変更を示す2本の縦線（複縦線）。
- **`end_barline`**: 細い線の後に太い線が続き、楽章や曲の終わりを示すもの（終止線）。
- **`repeat`**: 反復区間を示す、点の付いたバーライン（反復記号）。

### 1.2 バウンディングボックス（BBox）の方針
- **ラベル付けの単位**: 縦線1本を最小単位とします。複縦線や終止線を構成する線は、それぞれ**独立したBBox**として登録しなければなりません。
- **範囲**: 各BBoxは、1本の縦線を正確に囲む必要があります。
- **ラベル**: 複縦線を構成するBBoxはすべて `double_barline` とラベル付けします（`end_barline` も同様）。
  - *理由*: これにより、1本ずつの線を検出するCNNの学習と整合し、論理層がラベルと距離（`unit_size`）を使って線をまとめられます。

## 2. 機械学習（CNN）との連携

### 2.1 学習の方針
- **二値分類（現行）**: 本番のCNNは、バーラインかそれ以外かを判定する二値分類器です。この方針では、二値の学習データにおいてすべてのラベル（`barline`、`double_barline`、`end_barline`、`repeat`）を**ラベル1（正例）**として扱います。選定済みのモデルと閾値は、この方針ではなく[モデル資産の契約](../contracts/MODEL_ARTIFACT_CONTRACT.ja.md)と `configs/dense_full_pipeline.yaml` で定めます。
- **多クラス段階（将来）**: 詳細なラベルは、将来、線の種類を区別できる分類器の学習に使う可能性があります。現在、多クラス分類器は本番に含まれていません。

### 2.2 DeepScoresとの整合
- DeepScoresの「Label 3」（Barline）は、基本メタデータでは細かいサブクラスを持たず、さまざまな種類のバーラインを含みます。
- **方針**:
  - DeepScoresのデータは、細い（単一の）バーラインのサンプルの主な取得元として扱います。
  - 独自のGTで、`double` と `end` のバーラインの高品質なサンプルを用意します。
  - 将来の多クラス学習では、DeepScoresのサンプルを幅（ピクセル数）に基づいて「疑似ラベル付け」し、細い線と太い線を分けることができます。

## 3. 論理層（小節番号付け）

### 3.1 複数の線の候補の扱い
- CNNは、複縦線や終止線の中の線を個別に検出することがあります。
- **重複除去**: 論理層（`src/measure_numbering/numbering.py` の `MeasureNumberer`）は、**1.2 * unit_size**（`DEDUPLICATION_THRESHOLD_UNITS`。`unit_size` は五線間隔）の閾値内にある候補をまとめます。
- **スケール不変性**: 固定のピクセル数ではなく `unit_size` を使うことで、解像度や楽譜の大きさが違っても動作します。

## 4. 新しいラベル付け対象を追加するときの手順

この手順は、複縦線・終止線のラベルを導入したときに最初に使われました。新しい対象を追加するときにも使います。

1. **対象の選定**: さまざまな複縦線と終止線を含むページを3〜5ページ選びます。
2. **GUIでの作業**: `tools/gt_relabel_gui` を使い、上で定めた種類でラベルを付けます。
3. **検証**: 出力されたJSONが、論理的な「バーラインイベント」を正しく表していることを確認します。
4. **繰り返し**: 選んだ対象で検証できたら、GTの本格的な作成に進みます。
