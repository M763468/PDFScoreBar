この文書は、利用者向け補正アプリケーションについて、実際の成果物で繰り返し実行できる受入ランナーを説明します。このランナーは Issue #397 で導入されました。その受入の証拠とレビューの経緯は、末尾の過去の記録の節に残しています。

利用者向けレビューアプリケーションは、保持済みのレビューパッケージを読み込み、補正を記録し、正規のレビューエンジンを通じて適用します。正規のGTを編集することはなく、ブラウザからのリクエストで任意の入出力パスを選ぶこともありません。

実際の成果物による繰り返し可能なゲートは、新しいディレクトリで実行します。

```bash
python -m tools.review_correction.acceptance \
  --source-run /absolute/retained/single-page/run \
  --movement-review /absolute/retained/movement/package \
  --evidence-root logs/issue<N>/acceptance/<run> \
  --runtime-identity <immutable-image-id>
```

`<N>` には作業中のIssueの証拠ルートを使います。

固定ケースは、保持済みの本番の1ページと、保持済みのショスタコーヴィチの楽章レビューの根拠（元は Issue #354 と #346 のもの）を使います。ランナーは、HTTPリクエストを始める前に、パス、元の成果物のハッシュ、モデルの識別情報、ランタイム、補正内容、期待される効果を固定します。パスの調整を受けるのはコピーしたmanifestだけで、幾何、許容値、モデルの閾値は保たれます。楽章のゲートは、保存済みのページインデックス6を保ったまま、意図的に page_008 を選びます。過去の複数ページの実行には、連続した番号付けの回帰ベースラインに必要なメタデータが含まれていません。

Gitのメタデータがないコンテナで実行する場合は、`PDFSCOREBAR_SOURCE_COMMIT` に候補のcommitを設定します。manifestが必要とする保持済みの実行とモデルのディレクトリだけを読み取り専用でマウントし、出力用に隔離した候補のworktreeを加えます。メインのワークスペースやそのGitメタデータはマウントしないでください。`--prepare-only` は補正を適用せずに入力を固定してコピーするだけで、受入の合格結果ではありません。

ゲートは次を対象にします。MMRの番号付け（2小節目 2 → 3、次の段 6 → 7）、固定した内部の小節線の削除（物理小節 78 → 77、後の段 84 → 83）、レビュー済みの楽章リセット（24 → 1）、未確定の楽章（24 のまま）、補正の削除、古い結果の識別、その後の適用失敗、GTの経路の隔離。最終PDFのゲートは、固定した段の先頭の番号を確認し、埋め込まれたラスタ画像を、補正済みの番号付けをレンダリングしたものと比較して、PDFのプレビューを保持します。アプリケーションの状態は、正確な補正の識別情報について最新である必要があります。一方、パッケージの状態は混在したままでも構いません。

失敗・ブロックしたレポートはすべて保持してください。修正したハーネスで採点し直す場合は、可能な限り有効な保持済みの出力を再利用します。検出器のアルゴリズム、モデル、閾値は変わらないため、検出品質の全体評価はこれらの統合ゲートの対象外です。ブラウザでの作業の流れとローカルの限定テストが、これらのAPIと成果物のゲートを補います。

### ブラウザでの作業の流れ

Pythonコンテナに Node/Playwright がない場合は、用意されている[ブラウザ検証ランナー](LOCAL_VALIDATION.ja.md#ブラウザ検証)を、明示的な Chromium のパス、ネットワーク経路、ソースのマウント、証拠のマウントとともに使います。

Playwright モジュールと Chromium がインストールされている場合は、`tools.review_correction.server` で、書き込み可能な新しいコピーのパッケージを開き、次を実行します。

```bash
PLAYWRIGHT_MODULE=/path/to/playwright CHROMIUM_PATH=/path/to/chromium \
  node tools/review_correction/browser_acceptance.cjs \
  http://127.0.0.1:8010 logs/issue<N>/acceptance/<run>/browser
```

このスクリプトは保持済みの最初の小節を選び、実際のフォーム操作で保存、適用、PDFの取得、補正の削除を行います。pending/recorded/current/stale の状態遷移を確認し、スクリーンショット、状態のスナップショット、ダウンロードしたPDFを保持します。元の最初の小節の範囲が1である、新しいコピーのパッケージを使ってください。
