# Future Roadmap: Post-Heuristic Strategy

## 背景
ルールベースの画像処理（Heuristic）による FP 削減は限界（Safety Ceiling）に達しました。
これ以上の精度向上には、アプローチの転換が必要です。

## 推奨アプローチ

### 1. Interactive Verification (GUI Tool) -【推奨: 即効性あり】
「完全自動で削除する」ことを諦め、**「疑わしい候補を人間に提示する」** アプローチです。

- **実装案**:
  - FP の疑いがある候補（Heuristic 2-5 で引っかかったものなど）に「Warningフラグ」を立てる（削除はしない）。
  - OMR 結果修正 GUI（またはシンプルなビューア）で、Warning 付きのバーラインを赤色表示する。
  - ユーザーは「Tabキー」等で Warning 箇所のみを巡回し、不要なものを高速に削除する。
- **メリット**: TP 削除のリスク（FN）をゼロに保ったまま、作業効率を劇的に向上できる。

### 2. Model Retraining (上流工程の改善) -【中長期的】
根本原因である「バーラインの断片化」を解決します。

- **課題**: 現在のモデルは、かすれたバーラインを「複数の短い線」として検出してしまう。
- **対策**:
  - アノテーションデータを修正し、かすれた線も「1本のバーライン」として学習させる。
  - あるいは、新しい OMR アーキテクチャ（Transformer ベースの End-to-End Object Detection など）への移行を検討する。
- **コスト**: データセット作成と学習コストが高い。

### 3. Semantic / Logical Validation (音楽理論の導入) -【高難度】
画像特徴ではなく、「楽譜の論理」で判断します。

- **実装案**:
  - 音符（Note）と休符（Rest）、拍子記号（Time Signature）を認識する。
  - 各小節の拍数を計算し、「拍が余っている/足りない」場合に、その区切り線が正しいかを検証する。
- **課題**: 音符認識の精度が 100% でない場合、このロジック自体が破綻するリスクがある。Page 3 のような手書き風/低品質なスコアでは難易度が高い。

## 結論
短期的には **1. GUI 補助** の実装を推奨します。H2〜H5 で作成したロジックは「削除」には危険すぎますが、「警告」には有用な特徴量を含んでいます。これらを再利用可能です。
