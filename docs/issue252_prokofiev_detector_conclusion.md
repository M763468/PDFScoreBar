## Rejected side-context repair

The side-context experiment is scale-sensitive. Under the corrected SR-coordinate
contract, the verified probe results are:

```text
variant                       final candidates   target in final
canonical default             103                no
side-context width ratio 1    144                no
side-context width ratio 2    282                yes
side-context width ratio 4    447                yes
```

Width ratio `2.0` is the minimum tested setting that recovers the target. It is not a
narrow repair: it increases the pre-CNN candidate set from `103` to `282`. Width ratio
`4.0` expands it further to `447`.

The corrected production-order comparison of default versus width ratio `2.0` reports:

```text
CNN accepted candidates       = 98 -> 105
connector evidence equal      = true
system count                  = 12 -> 12
serialized component count    = 13 -> 13
component grouping equal      = true
page measure count            = 90 -> 91
last measure number           = 93 -> 94
changed geometry systems      = [0, 8]
changed numbering systems     = all 12 systems
classification                = candidate_page_wide_numbering_drift
```

The candidate is rejected because it changes unrelated page geometry and shifts final
numbering across the page. No side-context option, generic paper-overlap threshold,
CNN threshold, or experiment config is promoted to production.

The earlier `103 -> 482`, `98 -> 122`, and `96 -> 111` figures came from a comparison
that did not use the corrected SR/CNN versus original-numbering coordinate contract.
They remain historical evidence that the experiment was broad, but are not the
canonical Issue #252 result.

## Grouping and semantic interpretation

`numbering_final.pages[].systems[].staves[]` contains staff-mask connected components.
Its length is not a musical staff or divisi count. No maximum-two grouping rule is
introduced.

A same-x barline on another component is also not grouping evidence. The corrected
audit requires both:

1. actual membership in the final system containing the target component; and
2. positive connector evidence linking that component into the grouped system.

The corrected comparison runner:

- distinguishes the SR/CNN image from the original numbering image;
- validates their scale and coordinate contract;
- uses the production CNN downscale behavior;
- records the connector source explicitly;
- remaps MMR's serialized page key `44` to isolated page index `0`;
- writes distinct raw and remapped MMR override artifacts;
- writes distinct `numbering_base.json` and MMR-applied `numbering_final.json`;
- renders grouping, connector, CNN, deduplicated boundary, interval and number evidence
  directly on the original score image.

The target belongs to connector-supported system `6`, with serialized component indices
`[6, 7]`, in both routes. The owning-system measure count and complete deduplicated
boundary geometry are identical between default and candidate. The default route
already contains the owning-system boundary near:

```text
x = 847 / 854
```

The candidate route adds a high-scoring CNN instance at the target, but it does not add
a new measure to the target's owning system. Its row start changes from `36` to `37`
only because an additional measure in another system shifts page-wide numbering.

The default and candidate connector-evidence artifacts are identical. Their three MMR
overrides are also identical and are correctly remapped to isolated page index `0`.
Both routes report `base_equals_final = false`, confirming that the final artifacts are
MMR-applied outputs rather than copies of base numbering.

## Decision

Issue #252 does not promote a detector repair.

The remaining target is a real box-instance detector FN, but the corrected
connector-supported grouped comparison shows that it is redundant for the owning
system's deduplicated measure boundary. Recovering the box with side-context width
ratio `2.0` does not improve that system's measure geometry and instead introduces
unrelated page-wide drift.

The Issue #252 decision is therefore:

- keep the canonical detector and candidate-filter configuration unchanged;
- retain the first-loss, production-order comparison and overlay tools;
- record the target as a connector-grouped redundant box-instance FN;
- reject the side-context experiment;
- leave the independent accepted-grouping regression to Issue #254;
- leave promotion of other Issue #245 detector recoveries to Issue #255.

Issue #254 remains necessary because the current page grouping differs from the
accepted PR #219 result. That separate regression does not require Issue #252 to keep a
broad detector repair open: the current corrected route already provides positive
connector support and unchanged target-system geometry for the target-specific
promotion decision.
