# Task: ISSUE-070 (Issue #70)

## Context
直近の開発やテストの実行において、処理時間が予想以上にかかる（パフォーマンスの低下）現象が確認されています。
特にDocker Execによるコンテナへのアクセス頻度や、モデル推論時のメモリ使用量が影響している可能性が疑われています。
Issue #13 (Full Pipeline Phase 2: Batch optimization, VRAM management) と関連が深く、本調査の結果は #13 の VRAM管理戦略に反映させます。

## Problem
`make test` や `main.py --dry-run` などの実行時に応答が非常に遅く、タイムアウトになるケースも発生しています。
専用GPUメモリ（VRAM: RTX 4060 8GB）が不足し、共有GPUメモリ（システムメモリ）へスワップ・はみ出しが発生していることで極端な速度低下を招いている可能性があるため、検証が必要です。

## Goals
- パフォーマンス測定用のスクリプト、またはモニタリング手順の確立（`nvidia-smi`, `htop`, `nsys` などの活用）。
- 処理時間が極端に長くなる箇所の特定（ログ出力等によるプロファイリング）。
- VRAMはみ出し等、リソース枯渇の有無の確認と原因の特定。
- 設定変更（例: バッチサイズ縮小、onnxruntime-gpuのスレッド数調整、メモリ割り当て制限）やロジック改善による対策の実施。
- 対策後の実行時間とリソース使用量の改善確認。

## Non‑Goals
- モデルアーキテクチャの根本的な軽量化・再学習（推論環境の設定調整レベルに留める）。

## Acceptance Criteria / Definition of Done
- パフォーマンス測定用モニタリング手順が確立されドキュメント化されていること。
- 処理遅延の根本原因（VRAM不足、プロセスオーバーヘッド等）が特定されていること。
- ボトルネックを解消または回避する設定・コード修正が提案および実装されていること。
- `make test` が正常かつ妥当な時間内に完了し、VRAM (8GB) の範囲内に収まっていること。
- 対策によって他の機能にリグレッション（予測精度の低下など）が発生していないこと。
- 調査結果や対策内容が `Benchmarks.md` や `Log.md` に記録されていること。
