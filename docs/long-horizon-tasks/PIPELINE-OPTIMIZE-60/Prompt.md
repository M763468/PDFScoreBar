# Task: PIPELINE-OPTIMIZE-60 (Issue #60)

## Context
パイプライン各ステップ（PDF抽出、Homr推論、CNN、MMR）のデータ受け渡し（I/O）は、現在各ステップで中間JSONや画像を都度ディスクに読み書きしており、特に複数ページのバッチ処理時にファイルI/Oとプロセス起動のオーバーヘッドがボトルネックとなっている。
また、MMRステップではページごとに RapidOCR と ResNet18 がロードされており、1ページあたり数秒の遅延が発生している（Issue #24）。

## Problem
- ページごとの中間ファイルの頻繁な読み書きによるI/Oオーバーヘッド。
- MMR（`generate_numbering_overrides.py`）において、ページごとにモデル（RapidOCR, ResNet18）をロードすることによるプロセス起動・初期化のオーバーヘッド。

## Goals
- `src/pipeline/main.py` におけるデータフローの整理・最適化（インメモリ化または最小化）。
- MMRステップのバッチ化を実現し、モデルロードを1回に集約する（Issue #24の解決）。
- スループットの向上（特に複数ページ処理時）。

## Non‑Goals
- `pdf_to_images.py` の基本機能の変更（ただしI/Oの渡し方は変更対象）。
- CNN分類器自体のモデルアーキテクチャや重みの変更。

## Acceptance Criteria / Definition of Done
- `toy_symphony` および **他の主要な回帰テスト用データセット（例: smoke_test.yaml）** で、全ページの MMR 処理が1回のプロセス起動（またはモデルロード）で行われること。
- 改修前と後で、小節線検出および小節番号付与の結果（JSON出力内容）が完全に一致すること（精度デグレなしを複数データセットで確認）。
- **デバッグモード（または設定フラグ）が無効な場合、余分な中間ファイル（不要なJSONや画像）の出力が抑制されていること。**
- `make lint` および `make format` を通過すること。
