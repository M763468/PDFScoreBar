# SR Bypass Evaluation Report: Issue #25 (Interim)

## 1. 概要
SR（超解像）をバイパスした際の精度の影響を、全68ページの評価データセットを用いて厳密に検証した。
PR #76 で確立された「Golden Config」に基づき、過去に最高精度（FN=1）を達成した際の候補位置（Bands）を固定した状態で、画像ソースのみを差し替えて比較を行った。

## 2. 定量的結果 (Global 68 Pages)

| 構成 | 全体 Recall | TP / **FN** | 処理時間 (1枚) | VRAM |
| :--- | :---: | :---: | :---: | :---: |
| **SR x4 (最高精度モード)** | **100.0%** | 3580 / **1** | ~15秒以上 | 特大 |
| **Bypass (高速・標準モード)** | **99.6%** | 3566 / **15** | **~1.5秒** | 最小 |

### 増加した FN (14件) のスコア別内訳
- **Sibelius Violin Concerto**: +6件
- **Prokofiev Symphony 1**: +2件
- **Prokofiev Symphony 5**: +6件

## 3. 分析：SRの真の役割
今回の厳密な比較により、SRの主要な寄与は以下の点にあることが特定された。
- **Structural Repair (構造補完)**: 低解像度のままでは「インクの掠れ」や「周辺ノイズ」として CNN に判定（スコア低下）される極薄の線が、SR を通すことで「明確な線」として強調され、判定閾値をクリアできるようになる。
- **Bypass の限界**: 重心補正（Golden Config）によって座標のズレは吸収できるが、画像特徴そのものが低解像度で失われている場合、CNN による分類段階で FN が発生する。

## 4. 再現手順
`logs/issue53_full_eval_rescue_v1` (FN=1) の結果は、以下のコマンドで最初からのフルパイプラインとして再現可能。
```bash
make run-pipeline CONFIG=configs/evaluation2_sr_x4.yaml
```

## 5. 暫定結論と方針
- **実用性**: Bypass (SRなし) でも 99.6% の精度を維持しており、1ページあたり10倍以上の高速化が得られる。
- **今後の運用**:
    - **デフォルト**: `enable_sr: false` (Bypass) を推奨。
    - **最高精度オプション**: 完璧な網羅性が必要なケース（アーカイブ作成等）のために SR x4 を維持する。
