# Project Roadmap (March 2026)

Date: 2026-03-13
Status: Issue #13 (Phase 2) nearing completion.

## Overview
本ドキュメントは、Issue #13（Full Pipeline Phase 2）完了後の作業計画をまとめたものである。
主な目標は「評価サイクルの高速化」と「実行基盤の単一化によるSubprocessオーバーヘッドの排除」である。

---

## Phase 1: 評価基盤の高速化と安定化
パイプラインの性能を正しく、かつ迅速に評価できる状態を作る。

1.  **Issue #13 の最終検証とクローズ**
    - `evaluation2` データセットを用いたエンドツーエンド実行。
    - モデル永続化によるスループット向上の最終確認。
2.  **Issue #88: 評価スクリプト (`verify_final_comparison.py`) の真のバッチ化**
    - 現在1ページずつ呼び出しているループを、全ページ一括処理に変更。
    - 検証待ち時間を大幅に短縮し、開発サイクル（実装 -> 評価）を高速化する。

## Phase 2: 環境標準化と実行基盤の統合 (Subprocess Hopsの排除)
`docs/notes/REFACTOR_PLAN_20260312.md` に基づく最重要フェーズ。

1.  **Issue #5 & #7: 仮想環境・Dockerコンテナの整理と統合**
    - `sr_eval_gpu` 等の個別コンテナを単一の強力な開発用Dockerイメージへ統合。
    - **Issue #73 (共有メモリ拡張)** をこのタイミングで実施（コンテナ再構築に合わせる）。
2.  **Subprocess 排除リファクタリング**
    - `src/pipeline/python_env.py` による `docker exec` 経由の実行を廃止。
    - `homr` や `sr` 等を直接 Python モジュールとしてインポートし、インプロセスで実行可能にする。
3.  **Makefile インターフェースの統一**
    - `make run-pipeline`, `make test`, `make lint` 等の標準化。

## Phase 3: ロジック精密化と技術負債の返済
運用効率と検出精度の更なる向上。

1.  **Issue #45: CNN関連スクリプトの整理**
    - `experiments/` と `tools/` に分散したスクリプトの棚卸しと配置ルール適用。
2.  **Issue #43: Probe scan の探索範囲制限**
    - 余白領域の走査を制限し、ノイズ削減と処理の効率化を図る。

---

## 依存関係メモ
- **#88 (評価バッチ化)** は、Phase 2 の大規模なリファクタリングにおいて、挙動に差分が出ていないかを高速にチェックするために不可欠である。
- **#73 (共有メモリ)** は、Phase 2 のコンテナ統合と同時に実施することで、SR画像の高速転送基盤をセットアップする。
