# 将来的課題: さらなる精度向上（FN=0, FP=0）へのロードマップ

**⚠️ 注意 (DISCLAIMER):**
ここに記載されている手法（CNNの再学習や適応的閾値の導入）は、**絶対的な最終手段（Last Resorts）**です。
Issue #117 の本来の目的は「過去のバージョンのパイプラインで達成できていた 100% の結果を再現すること」であり、新しいアーキテクチャやモデルを発明することではありません。
まずは現在のコード（特にCNN画像スケーリングバグの修正後）でのバグ要因を完全に排除することを最優先とし、これらに着手するのは「過去のコードと完全にロジックが一致しているのに、どうしても精度が届かない」ことが証明された後のみとしてください。

---

## 1. 現状の限界
Issue #117 の修正により、実用上十分な精度（Recall > 98%）に到達しましたが、極限（100% / FP=0）を目指す上では以下の技術的トレードオフが残存しています。

- **CNN 閾値のジレンマ**: 超解像（SR）によるエッジのぼやけにより、正解の CNN スコアが 0.2 〜 0.4 に分布してしまうケースがある。
- **インク密度の画一性**: `min_ink_ratio: 0.70` はノイズ除去に強力だが、印刷品質の悪い「かすれた小節線」を誤って除去する場合がある。

## 2. 推奨される将来的な改善策

### ① CNN モデルの再学習 (DPI-Aware Training)
- **課題**: 現在のモデルは 1x (300-360 DPI) の画像で学習されている。
- **対策**: パイプライン内で実際に生成される 2x SR 画像、および `trim_box_to_ink` によってタイトに切り出されたパッチ画像を学習データに加え、ファインチューニングを行う。これにより、低スコアの FN を撲滅できる。

### ② 適応的インク密度閾値 (Adaptive Ink Ratio)
- **課題**: 小節線の太さや濃さはページごとに微妙に異なる。
- **対策**: 
    - ページ全体のインク分布（Histogram）から閾値を動的に決定する。
    - Homr 等で既に「高スコア」で確定している既存ボックスの平均インク比率を基準に、その 80% 程度を `min_ink_ratio` の下限として自動設定する。

### ③ アスペクト比フィルタの高度化
- **課題**: スタッカートや小さな記号が小節線候補に残る。
- **対策**: `min_height_ratio` だけでなく、`height / width` の比率（アスペクト比）が極端に小さい（横長、あるいは正方形に近い）候補をより厳格に弾くロジックを `candidate_filters.py` に追加する。

## 3. 結論
現在のアーキテクチャ（Native Filter + Box Tightening）は、これらの高度な改善を「プラグイン」として受け入れ可能な柔軟な設計になっています。
さらなる精度が必要な場合は、上記 ② の適応的閾値の導入から着手することを推奨します。
