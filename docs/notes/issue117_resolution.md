# Issue #117 調査・修正レポート (途中経過)

## 1. 概要
`v10` パイプラインにおいて発生していた Recall 低下（98.0%への後退）および FP の爆発的増加を調査しました。
現在、`Shostakovich-Festival_Overture_Va` データセットにおいては **100.0% Recall / 100.0% Precision** の復元に成功していますが、他のデータセット（Sibelius等）においては依然として数件の FN（未検出）が残存しており、**本Issueはまだ完全に解決していません（動作確認待ちの修正あり）。**

## 2. 判明した精度低下の真因と実施した対策
調査により、SR（超解像）導入に伴う複数の「サイレント・バグ」が特定されました。

1. **垂直重なり（VOV）の不一致（VOV Mismatch）**:
    * **原因**: SR空間での検出ボックスは五線領域を完全にカバーするため背が高くなるが、GTは1x空間のタイトなボックスである。このため重なり率（VOV）が閾値の 0.5 を下回るケースが発生していた。
    * **対策**: `trim_box_to_ink` を新規実装し、検出直後にインク密度をスキャンしてボックスを垂直方向にタイトに絞り込む処理を追加。
2. **座標スケーリングの漏れ（Coordinate Scaling Bug）**:
    * **原因**: Homr の検出結果（1x）を SR 空間（2x）の `probe_scan` に引き渡す際、座標のリサイズが漏れていた。これにより重複候補が大量に生成され FP が激増。
    * **対策**: `DetectorOrchestrator` で `existing_boxes` を正しくリサイズして後続へ渡すよう修正。
3. **自律的フィルタリングの欠如**:
    * **原因**: 過去の 100% 達成はGT作成用ツールによる手動フィルタリングに依存していた。
    * **対策**: `candidate_filters.py` を新設し、ネイティブ・ヒューリスティックフィルタ（左マージン、音部記号マスク等）を統合。

## 3. 【重要】新たに発覚した致命的なバグと未検証の修正
全データセットで100%に届かない原因を調査した結果、CNNスコアリング入力において致命的なバグが発覚しました。

4. **CNN画像ダウンスケールバグ (CNN Image Scaling Bug)**:
    * **原因**: `cnn_scoring.py` に対して「1xのオリジナル画像」を渡しているにもかかわらず、`input_image_scale=2.0`（SRスケール）という指定により、内部で「1x画像をさらに0.5倍に縮小してしまう」処理が走っていた。同時に候補の座標（2x）は1xにダウンスケールされるため、**画像と座標の完全な位置ズレ**が発生し、CNNが全く関係ないパッチを採点させられていた。
    * **対策（実装済・未検証）**: `candidate_rescale_factor` を導入し、画像のスケーリングと候補座標のスケーリングを完全に分離する修正をコードに適用・コミットしました。
