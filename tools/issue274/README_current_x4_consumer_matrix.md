# Issue #274 current-x4 consumer matrix

`run_current_x4_consumer_matrix.py` is the focused gate before attempting to remove
pinned x4 HOMR (C) from production.

It reuses the retained A/B/C/OMR producer artifacts from the completed Stage-E A/B
experiment and reruns **only PDFScoreBar-owned downstream detector work**:

- hybrid evidence selection;
- dense probe generation / candidate filtering;
- the PDFScoreBar barline CNN.

It does **not** rerun HOMR, Real-ESRGAN, OMR-DLN, MMR, or numbering.

## Why this matrix exists

The retained B-only substitution lost five greedy TPs on four pages.  The residual
trace shows two different mechanisms:

1. B can support an A box that C did not support.  The retained A box then acts as
   an existing-box suppression seed and prevents dense probe reconstruction from
   emitting multiple structural candidates (`Sym5/page_013` and the Sibelius
   structural cases).
2. Current PDFScoreBar thin-barline post-processing can change x4 evidence geometry
   so symmetric IoU rejects an otherwise directionally valid support relation
   (`Sym5/page_015`).

The experiment therefore crosses support policy and suppression identity instead
of tuning one threshold at a time.

## Matrix axes

### Support

- `c_iou`: retained pinned-x4 C, symmetric IoU control.
- `b_iou`: retained current-x4 B, current symmetric IoU policy.
- `b_directional`: B as evidence; x distance is normalized by Phase-A staff-space
  and A's staff slots must be covered by the evidence slots.  `alpha=0.30`,
  `gamma=0.60` are historical/stability calibration values, not acceptance proof.

OMR-DLN support remains at the current IoU rule in every cell so the matrix isolates
x4 HOMR consumer behavior.

### Existing-box suppression

- `legacy`: current PDFScoreBar dense-probe behavior.
- `best_band`: experiment-local one-existing-box/one-structural-band ownership.
- `disabled`: suppression disabled; causal upper bound only, never a production
  proposal.

`best_band` changes only PDFScoreBar's `has_existing_for_suppression` semantics.  It
does not change HOMR or the rest of dense-probe generation/rescue logic.

### Clef artifact

- `retained_c`: retain the C-derived clef mask as a diagnostic control.
- `none`: remove that artifact to expose a hidden downstream dependency.

The clef/key mask pixels are generated by upstream HOMR.  Discovering, persisting,
and handing that mask to candidate filters is PDFScoreBar orchestration.  If the
matrix proves the clef mask is required, the intended fix is to publish current
B's `clefs_keys` mask from the **same B inference**, not to preserve a second x4
HOMR execution.

See `HOMR_FEATURE_OWNERSHIP.md` for the full ownership classification.

## Mandatory replay sanity check

Before interpreting any experimental cell, the tool requires these two cells to
reproduce the previously saved focused A/B metrics exactly:

- `control_c_iou_legacy_retained_c_clef` -> retained control;
- `b_iou_legacy_retained_c_clef` -> retained B candidate.

If either differs, the report decision is
`invalid_matrix_replay_does_not_reproduce_retained_ab`.  In that state, no
architecture conclusion should be drawn.

## Interpretation order

1. Require exact control/B replay.
2. Check whether suppression-disabled cells recover true cardinality.  If not, the
   current theory is incomplete.
3. Check whether `best_band` recovers the same structure without the over-generation
   risk of globally disabling suppression.
4. Compare IoU vs directional support, especially `Sym5/page_015`.
5. Compare retained-C-clef vs no-clef cells.  A clef dependency means artifact
   handoff must be completed from current B; it does not justify another HOMR run.
6. Only then replay one selected consumer contract across all 68 retained pages.
